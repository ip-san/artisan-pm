# A5-06 / A14-03 設計メモ: テーマ切替(`ui_theme`)

状態: `blocked(要承認)`。全画面の見た目に触れる変更で、ビルド済み CSS の目視確認ができない環境では品質を保証できない。方式の選択も要る。

## 背景

Redmine は設定 `ui_theme`(管理者)でテーマ(`public/themes/`)を選べる。本アプリは Tailwind v4 の単一の見た目(`resources/css/app.css`、`@theme` は最小)で、Blade は `bg-white` / `text-gray-900` / `border-gray-200` など色を直接クラスで書いている(全ビューに散在)。

## 選択肢

1. **A. CSS 変数を挟む(推奨)**: よく使う色(背景・文字・境界・強調)を `--color-*` の意味名(`surface` / `text` / `border` / `accent`)にして `@theme` に定義し、Blade のクラスを意味名のクラス(`bg-surface` など)へ置換する。テーマは `<html data-theme="...">` の属性で変数値を差し替える。
   - 長所: 色の追加が CSS だけで済む。ダーク/ライト/ブランドカラーを同じ仕組みで。
   - 短所: 全ビュー(約 100 ファイル)のクラス置換が要る。取りこぼしはテーマ切替時に白抜け/読めない文字として出る。
2. **B. Tailwind の `dark:` バリアントを全所に足す**: 既存クラスに `dark:bg-gray-900` などを併記。ダークとライトの 2 択に限られ、記述量は A より多い。
3. **C. 上書き用 CSS で `!important` 的に既存クラスを再定義**: 置換は要らないが壊れやすく保守できない(非推奨)。

## 判断が要る点

1. 方式(推奨 A)と、提供するテーマ(ライト、ダーク、+管理者が選べるアクセント色?)。
2. 選択の単位: サイト全体の既定(設定 `ui_theme`)と、ユーザーごとの上書き(A14-03。プロフィール)の両方を入れるか。
3. 検証方法: 見た目の確認が要るため、承認後にビルド(`npm run build`)して実機で目視確認できる環境で進めること。Blade 側の置換は機械的にできるが、コントラストの調整は人の目が要る。

## 推奨案と分割

1. **A5-06a**(M): 意味名の色トークンを `app.css` に定義し、レイアウトと共通コンポーネント(`resources/views/components/`)を置換。
2. **A5-06b**(M〜L): 各画面(Volt)のクラス置換を画面群ごとにコミット。
3. **A14-03**(S): 設定 `ui_theme` とユーザー個人設定、`<html data-theme>` の出力。

## 影響範囲

`resources/css/app.css`、`resources/views/**`、レイアウト、プロフィール/設定画面。フロントエンドの再ビルドが必須。テストは色を検証しないため、テーマ属性の出力と設定の保存だけを対象にする。
